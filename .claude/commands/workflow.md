# Workflowコマンド - シンプルなワークフロー管理

## 🎯 概要
メインエージェント（あなた）が直接サブエージェントを順番に呼び出してワークフローを管理します。

## 📋 使い方

### 基本的なワークフロー
```bash
/workflow "タスクの説明"
```

実行すると、メインエージェントが以下を順番に実行：
1. @agent-plannerで計画作成
2. @agent-executorで実装
3. @agent-reviewerでレビュー
4. 必要に応じて繰り返し

## 🔄 実行フロー

### 1. 計画フェーズ
```
あなた: "まず計画を立てます"
↓
@planner "タスク: [タスクの説明]"
↓
docs/context.md に計画を記録
```

### 2. 実装フェーズ
```
あなた: "計画に基づいて実装します"
↓
docs/context.md から現在のステップを確認
↓
@executor "Step X.Xを実装"
↓
docs/context.md に結果を追記
```

### 3. レビューフェーズ
```
あなた: "実装内容をレビューします"
↓
@reviewer "直前の実装をレビュー"
↓
docs/context.md にレビュー結果を追記
```

### 4. 判断と継続
```
あなた: レビュー結果を確認
↓
必須修正あり → @executor で修正
修正なし → 次のステップへ
```

## 📝 コンテキスト管理

すべての情報は`docs/context.md`に集約：

```markdown
# ワークフローコンテキスト

## 📍 現在の状態
- フェーズ: planning
- ステップ: 1/10
- 最終更新: 2025-08-07 12:00

## 📋 計画
### Step 1.1: プロジェクト初期化
- Viteプロジェクト作成
- 依存関係インストール

## 🔨 実装結果
### Step 1.1 完了
- package.json作成
- vite.config.ts設定

## 👁️ レビュー結果
### Step 1.1 レビュー
- ✅ 設定は適切
- ⚠️ TypeScript設定を追加推奨

## ➡️ 次のアクション
Step 1.2: TypeScript設定追加
```

## 🎯 メインエージェントの判断基準

### 次のエージェントを呼ぶタイミング
- **@planner**: 新規タスク開始時、全ステップ完了時
- **@executor**: 計画があり、未実装ステップがある時
- **@reviewer**: 実装完了直後
- **修正**: レビューで必須修正が指摘された時

### ワークフロー終了条件
- すべてのステップが完了
- レビューで重大な問題がない
- ユーザーが終了を指示

## 💡 使用例

### 例1: 新規機能開発
```
あなた: 「ユーザー認証機能を実装します。workflowコマンドを実行します。」

1. @planner "ユーザー認証機能の実装計画"
2. docs/context.md確認
3. @executor "Step 1.1: Userモデル作成"
4. @reviewer "Userモデルの実装をレビュー"
5. 問題なければ次へ...
```

### 例2: バグ修正
```
あなた: 「ログインバグを修正します。」

1. @planner "ログインバグの調査と修正計画"
2. @executor "バグの原因調査"
3. @reviewer "調査結果の確認"
4. @executor "修正実装"
5. @reviewer "修正内容のレビュー"
```

## ⚡ 利点

1. **透明性**: すべての呼び出しがターミナルに表示
2. **シンプル**: 1つのコンテキストファイルのみ
3. **柔軟性**: 状況に応じて判断可能
4. **制御性**: メインエージェントが完全制御

## 🚨 注意事項

- このコマンドは概念的なもので、実際にはメインエージェント（あなた）が手動で各エージェントを呼び出します
- 完全自動化ではなく、半自動的なワークフローです
- 各ステップでユーザーの確認を求めることがあります
